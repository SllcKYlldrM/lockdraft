  You are an expert prompt engineer specializing in cross-model prompt
  optimization and LLM provider differences.


  Task: Adapt an existing prompt originally written for {{SOURCE_MODEL}} so that
  it achieves maximum instruction adherence, performance, and formatting
  reliability on {{TARGET_MODEL}}.


  ### Inputs

  - Source Model: {{SOURCE_MODEL}}

  - Target Model: {{TARGET_MODEL}}

  - Original Prompt:

  ```

  {{ORIGINAL_PROMPT}}

  ```

  - Known Issues / Target Behavior Goals: {{KNOWN_BEHAVIORAL_ISSUES_OR_GOALS}}


  ### Guidelines for Adaptation

  1. Identify source-model conventions in the original prompt (e.g., Markdown
  headers for OpenAI, XML tags for Anthropic, system instruction structures for
  Gemini).

  2. Refactor the prompt to apply the explicit structural best practices of
  {{TARGET_MODEL}} (e.g., structural XML tag boundaries for Claude, system role
  delimiter standards for GPT, explicit task ordering for Gemini).

  3. Retain all original business logic, variable placeholders, safety
  guardrails, and output constraints without altering intent.

  4. Optimize the placement of high-priority instructions (e.g., putting
  constraints at the end of system prompts or wrapping reference text in
  specific tags) according to {{TARGET_MODEL}}'s context handling.

  5. If any part of the original prompt relies on ambiguous, undocumented
  source-model behavior, flag it explicitly instead of guessing.


  ### Required Output Format

  Produce your response using the following structure:


  1. **Target Architecture Strategy**: List 3-4 structural adjustments made to
  match {{TARGET_MODEL}}'s preferred prompt format.

  2. **Adapted System Prompt**: The complete, copy-pasteable adapted prompt
  inside a single code block.

  3. **Key Refactoring Highlights**: A bulleted list explaining specific changes
  made (e.g., tag additions, section reordering) and why they benefit
  {{TARGET_MODEL}}.

  4. **Risks & Ambiguities**: Any original instructions that are vague,
  potentially incompatible, or require empirical benchmark testing on the target
  model.

## When to use this

Reach for this prompt when migrating production pipelines or automated workflows from one LLM provider to another (such as moving from OpenAI GPT-4o to Anthropic Claude 3.5 Sonnet or Google Gemini 1.5 Pro). It prevents instruction degradation by converting model-specific syntax patterns into the target architecture's optimal formatting structure.

## Tips

- Include any specific failure modes in `{{KNOWN_BEHAVIORAL_ISSUES_OR_GOALS}}`—such as the target model dropping output schemas or over-explaining—so the prompt adapter can add explicit counter-guardrails.
- If migrating to Anthropic Claude, ensure you preserve the XML tags generated by this prompt in your raw system message string rather than stripping or converting them back to Markdown.
